在应用详情“开发工具”中打开此源码、复制 AI 接手说明或构建并更新；在“源码版本”中保存本机 Git。构建成功后仍须明确确认更新。已安装实例保留数据和配置，源码变更不会直接覆盖运行副本。本机提交不等于远端备份，需要另行推送到已有远端。

`.env`、`.data/`、`user/`、`work/`、`node_modules/` 和真实密钥均不进入 Git 或构建材料；`.env.example` 仅为公开配置模板。受管数据使用平台提供的 `APP_DATA_DIR`，配置与凭据由应用实例保存。源码仓库删除后只能从远端取回已推送源码，无法据此恢复数据库、附件、密钥或未推送修改。

## 平台标准运行约束（2026-10-20 已确认）

应用在平台提供的一个原生窗口内运行：用户点击打开时，平台后台启动唯一受管 Node；关闭这个应用窗口就停止它；重复打开只聚焦原窗口，启动中的重复打开复用同一次启动。保存配置不启动或重启，运行中要明确重启，或关窗后再打开。平台管理主窗口 X 按最新要求正常退出整个平台并收尾全部业务窗口与受管 Node，不再仅隐藏托盘；不终止用户独立 Node。

业务代码不得通过 `window.open`、`target="_blank"`、其他 WebView、外部浏览器、脱离进程组的常驻后端或额外原生窗口扩展运行方式。表单、帮助与确认留在当前窗口内，不调用脚本 `alert/confirm/prompt` 作为业务弹窗；受控文件选择与系统权限继续按平台能力和用户操作执行。宿主负责拒绝新窗口及越界导航，作者同时遵守这些约束。取消／关闭后不得让迟到的启动结果重新弹窗。

所有应用统一在“我的项目”，Radio 以 Node 类型图标区分；项目详情与配置集中在页内带 tabs 的弹窗，缺必填时点击进入先开配置 tab，不禁用整个进入入口。列表统一不合并内部 Node 源码槽与 project-v1 的身份／数据，也不开放尚未支持的备份迁移。新增交互验收须另记，保存仍不自动启动。

网页使用同源 `/api`、`/tts` 和事件流；平台 Rust 代理向固定后端附加 Bearer，业务页面不应获取该凭据、平台管理令牌或用户 Key。每个应用端口使用独立 HttpOnly 会话 Cookie，Cookie 不转发给 Node。原生窗口关闭会撤销会话并取消代理流，再收尾本应用全部受管 Node 与普通子进程；不能只因主 Node 退出就报告已清理。失败或进程归属不明保留真实状态，不误杀其他应用和独立 Node。宿主硬崩溃、被强杀和逃离受管进程组后代的清理不能作绝对保证，实际支持与验证范围必须明确。

该应用是独立 Node 类型，不是 project-v1。平台的 AI 接手入口指向这个源码仓库，本文件 `documentation.development` 提供作者开发说明；使用说明在 `documentation.readme`。不要伪造 project ID、添加数据库说明来冒充平台项目，或套用其备份／导出／回收／迁移命令。已有源码、锁文件、真实数据库、附件、登录资料和恢复现场保持，固定平台身份及数据根不改。

开发者须从平台原生窗口验证打开、重复打开只聚焦、关闭后端退出、重开数据保留、配置生效、异常提示及实际播放。早期浏览器／HTTP 检查只作诊断补充，不能替代原生窗口验收。平台规则的仓库维护源为 `docs/app-window-runtime-contract.md`，交付 skill 内的 `references/app-window-runtime.md` 提供相同约束摘要；本文保留足够独立说明，不要求应用维护者访问平台仓库。

## 入口与兼容

- `server/app.mjs` 提供业务服务器工厂，不在导入时打开存储或监听端口。
- `server/index.mjs` 保留独立版入口，原 `scripts/dev.mjs` 及 `npm dev/start` 继续使用固定本地网页/音乐服务规则。
- `server/managed.mjs` 是受管单入口；Node 24 的内置 SQLite 与现有业务逻辑保持，不改表、不读取原库。
- AI 仍是现有 `server/claude.mjs` 的 Anthropic Messages 兼容 API；没有改为 OpenAI 协议。后端为新受管实例提供 DeepSeek 地址及 `deepseek-flash` 默认值，不读取或改写原独立实例的模型、配置或真实密钥。
- `server/music.mjs` 默认仍走原 HTTP 传输；管理态改为 `music-sdk.mjs` 的同进程函数传输。它只加载所需模块，不载入 SDK `main.js/server.js`，不监听第二端口，不运行 SDK 版本检测或 npm。

SDK 某些调用内部仍会按当前工作目录寻找 `.env`，因此受管入口必须先切换到隔离 `APP_TEMP_DIR`，设置系统临时目录，再动态加载 SDK。匿名临时令牌和请求辅助文件留在此目录。不得改为先 import SDK 后覆盖目录；SDK 日志内容可能带上游资料，管理态只发固定受限诊断到 stderr。

2026-10-20 真实匿名试用发现，SDK 4.41.1 的 `song_url_v1` 默认使用 xeapi；仅加载函数会跳过上游启动时的公钥准备，导致搜索成功但取播放地址失败。适配器现在仅在首次取播放地址时调用 SDK 自带的 `getXeapiPublicKey`，保留上游的响应签名/解密检查，并将结果以 0600 原子写入隔离临时目录。并发请求共用一次初始化，失败后下次可重试；启动、健康检查与搜索不触发此公钥请求。

公钥请求使用固定上游地址、五秒超时和 AbortSignal、禁止重定向，并限制请求/响应为 64 KiB。约束通过只匹配该地址的临时 Axios 拦截器传给 SDK helper，结束后立即移除，不改其他 SDK 请求。它没有新增账号登录或调用整套 `generateConfig/main`。这只解决公钥初始化的超时/取消；后续 SDK 歌曲请求仍可能不支持主动取消，不能把外层超时解释为底层网络已停止。

上游目前仅在启动流程准备一次 xeapi 公钥，`util/request` 读取后在进程中缓存；它没有像 neapi 那样实现明确的过期/刷新重试。本适配器也按每实例一次准备，尚未证明长期不断收听时不会遇到上游密钥轮换，不能声称已有自动恢复或全天运行保证。

## 试验协议 v1

控制为 UTF-8 NDJSON，单条上限 8192 字节，不接受不完整 JSON、错误实例/协议或未知消息。stdout 仅协议，stderr 日志；实例 token 只输入，不输出。

1. 管理器通过创建环境提供绝对、互不重叠且不包含源码项目的 `APP_DATA_DIR`、`APP_CACHE_DIR`、`APP_TEMP_DIR`。源码入口位置不充当数据目录。
2. 十秒内写入 `{"protocolVersion":1,"type":"initialize","instanceId":"trial_instance","token":"至少32字节的随机ASCII认证值"}`。收到有效初始化前不创建应用存储。真实管理器必须使用高强度随机 token，文档字符串只是示意。
3. 返回 `ready`：`{"protocolVersion":1,"type":"ready","instanceId":"trial_instance","host":"127.0.0.1","port":动态端口}`。不接受调用者指定固定监听端口，不提供静态页面。
4. `ping` 携同实例和字符串 `requestId`，返回同 `instanceId/requestId` 的 `pong`。
5. 所有 HTTP 请求携 `Authorization: Bearer <token>`。`GET /_platform/health` 返回 `{protocolVersion:1,instanceId,status:"ok"}`，仅验证本地，不连接外部。`/api/status` 同样需认证，本地配置/模块检查不代表远端可用；业务代理须处理 Origin/Host、会话、代次等平台门禁。
6. `shutdown` 携实例 ID，返回 `stopping` 后排空业务、关闭事件流、文件与数据库并退出。五秒超时或无效控制消息以非零退出；不能把 `stopping` 当作干净停止。stdin EOF 也停止。

业务界面使用同源根路径 `/api` 与 `/tts`，由平台每实例 Rust 代理提供，不需要让用户填写网页基址或直接访问后端。代理已实现 SSE、音频 Range、请求体限制及停止取消并有核心测试；原生窗口、真实播放和关窗启停仍须按新包分别验收，不能将本地路由或历史浏览器测试当作产品完整链路。

## 配置、秘密与数据

清单只声明两项环境变量：

| 环境变量 | 标准配置规则 | 代码用途 |
| --- | --- | --- |
| `ANTHROPIC_API_KEY` | 必需、秘密，无默认值 | DeepSeek API 凭据，保留现有变量名。 |
| `FISH_API_KEY` | 可选、秘密，无默认值 | 主持口播凭据；未配置时只显示文字并播放音乐。 |

后端默认使用 `https://api.deepseek.com/anthropic` 与 `deepseek-flash`；Fish 固定服务地址为 `https://api.fish.audio/v1/tts`，默认型号 `s2.1-pro-free`。两把密钥足以启动节目生成和口播，不发送 `reference_id`，由 Fish 处理默认音色。地址、模型和音色不出现在平台配置表单中。

字段只包含 `label/type/required/secret/description/howToGet/helpUrl/placeholder`，不设置密钥默认值，不再关联未声明的 `endpointField`。平台须在启动前检查 DeepSeek 密钥。直接启动无密钥的子进程仅用于隔离生命周期测试，不表示标准配置已通过。

平台把秘密保存在各应用本机槽 `configuration/credentials/`，目录 `0700`、文件 `0600`，是文件权限保护的明文。普通读取只显示“已设置”，不把密钥放入源码、分享包或 Git。旧独立入口的高级环境变量兼容读取保留，但平台不声明或注入它们；受管入口不导入原 `.env`。`PORT` 与 `NETEASE_API_BASE_URL` 仍由动态端口和同进程音乐传输代替。

受管模式的库为 `APP_DATA_DIR/state.db`，品味为 `APP_DATA_DIR/profile/taste.md`；TTS 输出在缓存目录。`createStore` 的新增显式路径选项不改变独立版默认 `.data/state.db` 和 `user/taste.md`。

原音乐 Cookie 仍属于独立版业务库存储方案。受管模式禁用扫码、轮询和注销，不读取库内 Cookie；真实账号开放前必须先设计独立秘密存储、SDK Cookie 适配与归档排除，不能靠导出时搜索擦除。较早试验尚无平台配置持久化／秘密绑定，只用人工值或经授权的临时 DeepSeek 注入；当前本机私有文件与配置注入是后续平台实现。本机槽与本项目源码不同，秘密仍不保存到前端、作者清单、`.env`、分享包或 Git，保存后的常规读取仅显示“已设置”状态。

停止时等待正在执行的业务；底层 SDK/请求不都支持主动取消，超时会异常退出并保留试验数据。没有自动备份或一致性恢复保证；不可借受管入口绕过平台现有维护、恢复、迁移、回收保护。
